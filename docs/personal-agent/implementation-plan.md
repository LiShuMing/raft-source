# v0.2 实施顺序与验收

本计划以设计与模拟原型为起点。2026-10-28 已落地的部分与实际验收见[实现记录](implementation-v02.md)；A–D 是完整工作包，不因首轮实现而全部标为完成。每项验收保留版本、输入、执行节点、任务/Run、日志与实际文件。

## A：一个可以日用的助理

1. 个人任务读模型：覆盖当前用户DM/工作组任务，保留旧频道列表接口；分页与权限独立测试。
2. Bot导航/资料与对话工作条：替换空首页，使用真实状态投影；草稿、附件与失败保留。
3. 本地Agent/API引导：探测、认证、最小真实执行分层；三种runtime分别记录能力。
4. TaskRun关联：消息回执、runtime消费、业务状态分开；发送幂等、停止、恢复与队列可见。
5. 成果逻辑版本与预览：文件存在、来源与检查范围入库，修订不覆盖旧版本。

出口：公开资料研究、本地测试目录整理、仓库只读检查各完成至少三次；至少一次中途改要求与一次成果修订。无连接时不能显示假工作中。

## B：真实工具、接管与决定

1. 对话内应用连接卡，完成授权回原Run；连接撤销即时影响下次调用。
2. 受管浏览器适配器与独占控制租约，人类接管时拒绝旧epoch输入。
3. 外部动作ActionRequest、可编辑草稿、一次性决定、执行回执与unknown核验。
4. 待处理聚合与回到来源；拒绝、过期、重复点击、多端冲突反馈。
5. 工作组子任务与唯一负责人，限制并发、深度和重复交接。

出口：测试账户流程完成“整理资料→连接→登录接管→准备写入→修改草稿→批准这一版→取得真实回执”。在平台可控模式验证，可信原生模式单独记录能力限制。

## C：长期工作

1. 明确偏好的记忆卡、来源、更正、停用与作用域；与原生记忆区分。
2. 技能草稿、版本、启用与输入校验；从已验收成果生成。
3. Routine/Occurrence账本与既有reminder对接，规则预览、试跑、启停和历史。
4. 缺数据、漏跑、重叠、预算、连续失败与通知去重策略。
5. 搜索成果、消息、技能、定时工作，服务端权限过滤。

出口：真实任务→技能→试跑→周期执行→无变化静默→新成果通知→暂停，且重启后不会重复外部写。测试时钟仅用于计划单测，实际执行也需一次真计时证据。

## D：Mac交付与框架决策

1. 安装/升级、后台进程监督、菜单栏、关闭窗口与退出行为。
2. 本地文件选择/打开、系统通知、按需OS权限与敏感输入处理。
3. GPUI真实DM切片，满足[技术闸门](technical-design-v02.md#7-mac与gpui-kit决策)后再迁移更多界面。
4. 睡眠/唤醒、重启、网络与节点认证恢复；不自动迁移活动任务。

出口：用户新环境按产品流程完成配置与首次成果，不手动改库、不需要工程师代运行命令。构建与签名/安装检查、实际UI检查分别留证。

## 必须通过的故障场景

| 场景 | 期望结果 | 失败即否决 |
| --- | --- | --- |
| 消息已提交但HTTP回执丢失 | 同幂等键找到原任务 | 多建任务/重复派发 |
| DM任务在个人入口查询 | 可见且仅授权用户可查 | 空列表或越权摘要 |
| 执行中发补充 | driver按能力steer/排队并有回执 | 发出即显示已应用 |
| 取消时节点掉线 | 状态待确认，可核查/接管 | 立即标停止成功 |
| 人类接管时旧Bot仍输入 | epoch过旧被拒绝 | 同时争抢浏览器 |
| 批准后草稿/附件改变 | 旧决定失效，新版重批 | 用旧批准发新版 |
| 两端重复批准 | 一次消费，另一端返回已处理 | 执行两次 |
| 外部发送超时 | unknown，查询原服务再决定 | 自动重发 |
| 定时任务跨重启/节点重连 | 同occurrence只认领一次 | 重复副作用 |
| 本机睡眠超过补跑窗 | 记录错过，显示下次 | 伪造按时完成 |
| 两次周期重叠 | 合并或跳过并留原因 | 无限堆队列 |
| DST前后/改时区 | 展示实际日期，按既定规则唯一执行 | 固定UTC偏移冒充IANA时区 |
| 数据过期/缺失 | 降级/失败，保留部分成果 | 旧数据当最新 |
| 记忆更正/撤销 | 后续检索仅新有效版 | 重建时旧项回流 |
| 跨端打开本地成果 | 显示本机限定或经授权上传 | 暗中上传/路径假可用 |
| 标准部署回归 | 原频道、鉴权和任务语义不变 | 新个人默认破坏旧工作空间 |

## 产品指标与证据

目标：配置后首次成果≤10分钟、同一逻辑动作重复副作用为0、失败后草稿不丢失、待处理可一次定位来源。统计有用成果率、纠错/接管次数、恢复成功率、无意义通知与每任务usage；没有usage或价格时显示未知。目标值尚无实测。

实际验收需两份结果：单机PGlite/本地节点，以及标准PostgreSQL/远端节点。后者未做时，不能宣称多端同步完成。竞品功能覆盖由[对照表](grok-functional-reference.md)追踪；实现完成率不得从原型按钮可点击计算。
