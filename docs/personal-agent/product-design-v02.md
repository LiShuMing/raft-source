# Personal Agent 产品设计 v0.2

设计日期：2026-10-27。状态：产品与交互规格，供实现评审。本文取代 v0.1 首页方案。当前运行代码只完成个人入口与中性主题；以下目标能力不等于已经实现。

## 1. 产品要交付什么

一个人在 Mac 上管理长期使用的 AI 助理。每个助理有名字、职责、记忆和可接续的工作环境。用户通过消息交代工作，助理调用工具或本地 Agent，交回可检查的成果；遇到登录、授权或关键决定时，在原对话请求处理。成功的方法可以保存，之后按时间重复执行。

主对象从“新任务输入框”改为“持续工作的助理”。已有用户打开上次使用的助理；侧栏显示助理与工作组；任务、文件、电脑、记忆在这段长期关系中组织。新用户先完成简短的创建流程。

与 Grok Bot 的产品差异是允许用户决定执行方式：沿用已安装、已登录的本地 Agent，或使用自有 API 驱动平台内置 Agent。两者共享消息和成果，实际能力按运行时展示。竞品事实与产品推导见 [功能对照](grok-functional-reference.md)，本文后续均为本产品的设计决定。

### 一期的三个完整闭环

1. **委托与交付**：建立助理 → 发资料和目标 → 看进展 → 补充约束 → 打开成果 → 修订或结束。
2. **使用真实工具**：发现缺连接 → 在对话连接应用/选目录 → 看准备执行的动作 → 批准或接管 → 回到任务 → 核对回执。
3. **形成长期工作**：验收一次成果 → 保存技能 → 试运行 → 配周期 → 后台执行 → 有结果/异常才通知 → 看历史、暂停或修改。

一期必须同时覆盖这三条链路。聊天壳、模型选择器与任务看板不足以构成完整产品。

## 2. 六个用户对象

| 对象 | 用户理解 | 关键边界 |
| --- | --- | --- |
| 助理 Bot | 长期负责某类工作的伙伴 | 名称、职责、默认执行配置、技能与记忆；不为每次运行新建 Bot |
| 对话 | 我和助理/工作组的交流 | 长期保留；任务在其中有入口 |
| 任务 / 执行尝试 | 一次有交付条件的工作 / 执行它的一次尝试 | 一个任务可有多个 Run；重试保留副作用记录 |
| 工作环境 | 电脑、目录、浏览器和连接 | 执行位置可见；工作目录不自动构成权限隔离 |
| 成果 | 生成的文档、文件或变更 | 可打开，带版本、来源、位置和检查范围 |
| 技能 / 定时工作 | 确认过的做法 / 什么时候做 | 绑定版本、输入、负责人、时区、预算和通知规则 |

模型、运行时和设备在设置中分别配置。用户发消息时不必每次选择模型。对话头部显示“这台 Mac · Codex”，点击检查或修改下次任务的配置。

## 3. 主窗口与信息架构

默认两栏：232px 侧栏与弹性对话区。打开电脑、成果或助理资料时，才出现右侧 320–440px 检查区。初始窗口建议 1280×840，最小 900×640；宽度不足时检查区覆盖主区，以返回按钮回到对话。390px 小屏采用单层导航。

```text

  日常助理
```

侧栏不常驻频道、成员管理、模型枚举和调试日志。“待处理”聚合真正需要用户动作的事项，“资料库”收集可复用结果；任务历史在助理资料和搜索中查找。默认页面是助理会话，不再是填完即走的空首页。

### 视觉、键盘和无障碍

白色正文、浅灰侧栏、中性深色主操作、细分隔线；深色主题保持同一层次。禁止黄色品牌底色、大面积渐变、装饰统计和默认展开的轨迹。状态有文字与图标，颜色只辅助。正文建议 14px/22px、宽约 720px，侧栏13px。主界面不放常驻模式选择器，成果确认后再出现保存技能和定时工作入口。

Cmd+K搜索、Cmd+N新建、Cmd+,设置、Cmd+B收侧栏、Esc关检查区/弹窗。Enter发送，Shift+Enter换行，中文输入法合成期间不发送。焦点可见；弹窗约束焦点，关闭后返回触发处；流式内容只朗读阶段与终态。悬停操作有键盘等价入口。

## 4. 首次使用与创建助理

启动器确认本地服务与身份可用，再问“你想怎样运行助理？”：

| 路径 | 用户看到什么 | 成功条件 | 失败反馈 |
| --- | --- | --- | --- |
| 使用已有 Agent | 检测到的 Codex / Claude Code、版本、账号状态 | 程序存在、认证、最小真实执行分别通过 | 明确失败步骤，给登录/安装说明入口 |
| 使用模型 API | 供应商、协议、地址、模型、凭证和执行节点 | 选定节点最小模型调用通过；工具能力另测 | 保留表单，区分网络/认证/模型/能力失败 |

检测只查看安装与状态，不顺带扫描任意文件。API key 通过专用秘密字段保存，不进对话和浏览器存储。选择任务目录，说明是复制附件到管理目录，还是让可信本地Agent访问原目录。给助理命名、写一句职责，创建后直接进入对话。

“稍后配置”可以浏览，发送按钮解释缺少什么。第一个任务可用用户附件或公开来源；屏幕、麦克风和自动化权限在实际使用时才请求。没有屏幕权限仍能使用结构化工具。

### 新建入口与资料

Cmd+N统一提供已有助理、创建助理、创建工作组。创建最少只填名称与职责，继承已确认的默认执行配置，提交前可展开修改。不默认复制另一助理的私有记忆和历史。

资料含职责、记忆、技能、定时工作、执行设置、历史。隐藏只影响侧栏；停止任务、暂停定时工作、归档和删除分别表达。归档前列出活动任务与定时工作，由用户选择结束或保留，不能把隐藏当作停止。

## 5. 对话、任务与中途修改

支持文本、URL、粘贴图片、附件；`@`选择助理或应用，`/`选择技能。引用存稳定ID，改名不改变目标。附件有上传进度、失败和重试，准备好后才交付执行。草稿按对话保存。

有交付要求的请求创建任务；简短问答可以只产生消息。不清楚时问一个关键问题，发送菜单提供“作为新任务”，不只依赖模型推断。执行期间：

- 支持steer的运行时显示“补充当前工作”，先显示已送达/待应用，收到runtime确认才显示已应用。
- 只能排队的显示“加入下一步”，尚未消费的输入可取消。
- “新任务”形成独立Task；同Bot的一个交互会话串行，其他Bot可以并行。

工作条显示负责人、目标、阶段、最近真实进展与执行位置，展开看子步骤和工具轨迹，不暴露隐藏思维链。无事件显示暂无新进展，不生成假百分比。

停止先变成“正在停止”，收到执行器确认后才成为已停止；超时显示“停止状态待确认”。停止不撤销已发送消息或已改文件。用户消息优先于后台工作，实际中断方式仍由driver能力决定。

### 工作组与交接

一期支持用户选多个助理建组、@点名和可见子任务。每个子任务有唯一负责人、输入、完成条件和返回位置；主负责人汇总。服务端限制交接深度、并行数、循环与预算。

敏感审批内容只给授权的人展示，组内看到脱敏等待状态。子Agent不继承所有连接。自主创建团队放到后续，一期不会因宽泛目标无限生成Bot。

## 6. 工作环境、工具与接管

“工作环境”打开检查区，显示节点、目录、工具来源、最后连接时间。关闭预览不会停止在线执行器。

| 方式 | 一期交互 | 执行要求 |
| --- | --- | --- |
| 应用工具 / MCP | 对话内连接卡列账户与能力，完成后回原任务 | 优先结构化工具；凭证代理；参数与回执可审计 |
| 文件 / 终端 | 目录、执行摘要、产出与diff | 平台可控执行或明确可信本地模式 |
| 受管浏览器 | 页面预览、阶段、接管/交还 | 独占控制租约；截图/DOM事件归属Run |
| 本机桌面 | 按需OS权限，显示具体应用与设备 | 有能力且验证后才启用；shell不等于已有桌面操作 |
| 远端电脑 | 选择授权在线节点，展示独立环境 | 文件、登录和本地账号不自动迁移 |

一期优先受管浏览器，并保留桌面接入点；不承诺任意应用可靠自动化。无适配器的runtime显示未支持，不能露出假电脑预览。

### 登录接管

消息说明“需要在Notion登录才能读取所选页面”。“打开并接管”获得控制租约，Agent操作暂停；用户完成后点“我已完成”，检查页面状态、释放租约、恢复任务。密码/验证码不进入聊天与普通事件。租约掉线/过期保持暂停，避免争抢输入。

连接默认属于个人空间，但按Bot显式授予使用权。浏览器profile的共享范围单独展示；多个窗口不构成隔离，需要隔离则用不同profile/节点。

### 本机与常在线执行

本机关闭窗口后由后台服务继续；服务退出、断网和睡眠影响执行。菜单栏显示运行/待处理数量，退出时告知影响。远端在线节点才支持本机合盖后继续。

改节点默认只影响后续Run。迁移活动任务须先停、检查恢复与文件/凭证依赖，再开新尝试；离线后不静默转移数据和工作。

## 7. 草稿、审批和待处理

待处理聚合问题、缺连接、接管、待批准动作，并回到来源消息；成果待验收单独分类，不等于权限审批。

发送草稿完整展示账号、收件人、主题、正文、附件版本，可直接编辑。编辑生成新版本，旧批准失效。按钮为“批准并发送这一版”“暂不发送”，点赞不算批准。

动作卡包含：对象/目标账户、操作、当前值与拟议值、内容或diff、范围、触发任务、工具、有效期、回执。关键内容默认展开，原始参数次级。

批准绑定用户、Run、actionId、参数摘要、工具/连接、设备代际、有效期。服务端版本比较并一次性消费。撤销连接、改参数、迁移或超时后重批；多端同时点击只有一个成功结果。

连接器/受管工具在执行边界拦截。原生Agent若仍有不受控shell/浏览器，设置必须写明“可信本地模式：平台无法逐项阻止本机操作”，不能宣称所有动作均审批。强制审批模式需要完成driver与工具出口约束。

回执区分已接受、已确认发送、结果未知。超时无法查询时先核验，不自动重发。拒绝保留草稿，助理可完成其他部分，不直接终结整项工作。

## 8. 成果、资料库与搜索

成果卡有名称、类型、版本、时间、实际位置、来源任务和检查结果。右区预览Markdown、图片、PDF、文本/diff，其余打开/导出。本地成果在其他端显示“文件仅在该Mac”，用户选择上传后才跨端可读。

修订保留v1并生成v2，关联同一逻辑成果；可选版本、看差异、回原对话。发布/分享是独立动作，生成文件不等于公开。

资料库为文件列表，按Bot/日期/类型筛选；收藏是标记。Cmd+K查助理、任务、消息、成果、技能与定时工作，并定位准确对象。权限过滤在服务端，不能先泄露摘要再由前端隐藏。

## 9. 可检查的记忆

一期提供明确偏好的查看、添加、更正与停用。每项显示内容、来源消息、时间、适用范围（本人/Bot/项目）和状态。候选记忆与用户明确保存的规则分开；临时要求不自动永久化。

“记住：报告优先官方来源”产生可撤销的记忆卡；“仅这次”限定任务。冲突显示替换关系，旧项失效，检索只用有效版本。共享记忆需用户明确选择。

平台记忆与原生runtime记忆各有来源。不支持双向管理时，只注入平台上下文，删除不宣称清空原生历史。删除撤出后续检索/派发；活动会话已读取时需重建上下文；备份按留存策略处理。

## 10. 技能与定时工作

成果的“保存为技能”先建草稿：使用条件、输入、步骤、应用/目录、输出、校验、失败处理与需批准动作。确认生成版本，默认当前Bot使用，可选共享，不复制凭证。

平台技能以versioned context交给driver，支持时可导出到原生技能目录，不覆盖现有文件；重名显式选择。示范录制后续加入，产物也先是草稿。

“工作日九点再做一次”生成定时工作预填卡，可在对话确认或侧栏管理。必填：负责人、技能/指令版本、输入、节点、IANA时区、重复规则、下一次运行、验收、缺数据策略、通知、每次预算。保存前展示下三次**具体日期与时区**。

一期支持每天/工作日/每周，后续扩事件触发。操作包括试运行、保存启用、暂停、修改、历史。试运行做真实任务，使用同样的审批；只解析时间不算试运行。

### 调度契约

- scheduleVersion + scheduledFor 唯一，重启不重复建任务，Run固定技能/配置版本。
- 默认不重叠，上轮未结束则合并一次待执行，记录跳过原因。
- 默认只补最近一次且限两小时；超窗记错过，用户可立即运行或等下次。窗口可配置。
- DST不存在的时刻移到当日第一个有效时刻，重复时刻只跑第一次；保存展示实际计划。
- 数据缺失/陈旧标降级或失败，不冒充最新成果；有部分产出则保留。
- 默认新成果、待处理和持续失败才通知，无变化静默；连续三次失败暂停并通知一次。
- 暂停影响未来运行，是否停当前单独选择；改配置用版本比较，不重做已执行/结果未知的副作用。

## 11. 本地Agent、模型API与设备

“应用与连接”区分应用账号（服务访问）、Agent运行时（工作执行）、模型API（推理供应商）、设备（位置）。不能混成API key列表。

| 配置页 | 最少字段 | 检查 |
| --- | --- | --- |
| 本地Agent | 程序、版本、账号、目录 | 发现/认证/真实执行；steer、取消、恢复、审批能力 |
| 模型API | 名称、协议、base URL、凭证、模型、节点 | 文本、工具、流式分别验证；模型列表不等于可用 |
| 设备 | 名称、身份、在线时间、平台、能力 | 当前运行、目录、睡眠影响、升级/撤销 |
| 应用连接 | 服务、账号、能力、Bot授权 | 过期、重连、撤销、最近使用 |

修改默认影响下次Run；不自动改用未选择的第三方。凭证不导出、不进日志。预算使用可得usage，只有token时标估算，价格未知就显示未知；达到上限停在检查点。

## 12. 状态与恢复

任务事实、执行尝试、用户处理分开保存、统一投影。现有in_review不能直接标为权限审批。

| 界面状态 | 事实依据 | 用户动作 |
| --- | --- | --- |
| 正在提交 | 幂等键存在，请求未确认 | 保留输入，查询/重试原请求 |
| 已接收 | 消息与任务已提交 | 等待执行，不显示工作中 |
| 等待设备/排队 | 无能力或租约 | 看原因、取消、明确改节点 |
| 工作中 | Run已认领且runtime确认 | 补充、停止、看过程 |
| 需要你处理 | 有有效问题/连接/审批/接管 | 在具体卡完成操作 |
| 暂停/恢复中 | 有检查点或中断事实 | 恢复原节点、显式新尝试 |
| 待验收 | 成果可访问、检查范围已提交 | 打开、修订、结束 |
| 已完成/停止/失败 | 持久终态与回执 | 查成果、原因、重试 |
| 结果待确认 | 可能完成但回执不明确 | 查询原服务，核验后决定 |

重连按cursor补事件，服务重启按Run与session恢复；已持久消息不能重复交给模型。无法证明session是否消费时显示待确认。断线不能变空列表，失败不清草稿。

## 13. Mac生命周期与多端

一期Mac日用版包含后台服务、文件选择、系统通知、菜单栏、打开成果、接管和键盘。通知默认隐藏敏感正文，点击回对象；免打扰合并非紧急结果，稳定键去重。

后续Web/手机接同一控制服务，不复制本地库做双主。手机委托、看进展、审批和成果，执行仍属授权节点。离线可存草稿，审批必须联网核对版本；双端只有一次消费。远程访问需用户配置可达控制端及授权，loopback不自动公开。跨端消息可见不意味着任意本地文件可下载。

## 14. 一期范围与验收

| 阶段 | 交付 | 出口条件 |
| --- | --- | --- |
| A 工作关系 | Bot/资料、会话、个人任务读模型、本地Agent/API引导、成果 | 研究/文件/代码可完成修订，不手工改库启动 |
| B 真实工具 | 应用/MCP、受管浏览器、草稿、动作卡、接管、待处理 | 登录→审批→回执完整；拒绝/过期/撤销/冲突可恢复 |
| C 长期工作 | 记忆、技能版本、基本定时工作、历史、通知 | 成功→技能→试跑→自动跑→暂停，重启不重复副作用 |
| D Mac日用 | 安装/后台/菜单栏、文件通知、睡眠恢复、能力声明 | 冷启动/重启、中文输入、长对话与故障验收通过 |

A–D都属于一期。完整移动客户端、实时语音、示范学习、云电脑托管、插件商店、自主扩编与企业管理属于下一期。听写可在系统能力验证后加入，不阻塞文字闭环。

首次配置后十分钟取得可打开成果是目标，尚无测量值。源码、新契约见[技术设计](technical-design-v02.md)，任务拆解和否决项见[实施与验收](implementation-plan.md)。
