# Grok Bot 功能机制与设计取舍

核验日期：2026-10-27。依据官方公开文档，未登录完成真实任务、未取得私有实现或体验指标。官方能力为文档描述，机制判断为推导，本产品方案为设计。`grok` CLI driver不等于Grok Bot服务接入。

| 官方能力与来源 | 体验机制（推导） | 本产品决定 |
| --- | --- | --- |
| [长期Bot](https://docs.x.ai/grok-bot/bots)：职责、对话与背景持续积累，可固定/隐藏 | 重复找同一负责人，减少交代背景 | Bot作为侧栏主对象，职责/记忆/技能/配置可查；隐藏不暂停 |
| [消息与协作](https://docs.x.ai/grok-bot/chat-and-collaboration)：附件、语音、引用应用/技能、中途补充、编辑发送草稿、组内交接 | 工作在同一对话推进，少切页面 | 文字/附件、@、/、草稿、任务内补充纳入一期；按driver区分steer/队列；实时语音后续 |
| [持久电脑](https://docs.x.ai/grok-bot/computer-and-apps)：文件、登录、终端持续；账号共享电脑，Bot有各自屏幕 | 降低重登录成本，后台执行独立于客户端 | 本地Mac先行，在线远端可选；profile共享范围可见，窗口不作为隔离边界 |
| [应用与接管](https://docs.x.ai/grok-bot/computer-and-apps)：应用工具优先，其他路径用浏览器，敏感步骤接管 | 工具选可靠路径，遇到登录仍可继续 | 复用应用授权，新增浏览器控制租约，连接/接管回原Run |
| [审批](https://docs.x.ai/grok-bot/approvals-security-and-privacy)：具体动作批准/拒绝、规则与敏感输入 | 有具体内容可检查时再决策 | 卡片绑定参数版本、连接、一次性回执；可信原生与平台可控模式分开 |
| [技能](https://docs.x.ai/grok-bot/skills-routines-and-automations)：从成功流程保存做法，示范学习逐步开放 | 复用经校验步骤，减少重新发明 | 一期从验收任务生成技能草稿，检查边界再启用；录制学习后续 |
| [定时工作](https://docs.x.ai/grok-bot/skills-routines-and-automations)：负责人、时间/事件、试跑、暂停、历史 | 让助理长期负责，平台承担调度 | 一期时间触发，时区与下三次日期可见；复用reminder并补运行账本 |
| [成果与Pages](https://docs.x.ai/grok-bot/files-and-results)：对话预览文件、修订、持续更新页面 | 留下可继续使用的工作对象 | 一期成果版本和预览；互动Page用受限格式，公开分享独立处理 |
| [设置](https://docs.x.ai/grok-bot/settings-and-notifications)：统一模型管理、设备/通知、本地执行 | 日常无需反复技术选择 | 默认隐藏模型；本产品额外提供本地Agent/API两条路径，修改作用于下次Run |
| [移动端](https://docs.x.ai/grok-bot/mobile)：同Bot、会话和电脑，移动发起/审批/查看；部分编辑限桌面 | 离开桌面仍能解除阻塞 | 一期统一对象/事件，手机后续接入；本机睡眠如实等待设备 |
| [上下文积累](https://docs.x.ai/grok-bot/overview)：角色、偏好、工作背景跨会话持续 | 长期关系保持连续性 | 平台记忆有来源和更正入口，不假定能完全管理原生runtime记忆 |

## 上一版缺了什么

把复杂度收进“执行与连接”解决了颜色和拥挤，但仍是填目标后跳DM，没有完整回答：Bot如何长期负责、后台工作在哪里、如何接管、成果如何修订、一次成功如何成为定时职责。

v0.2保留简洁外观，补齐可操作对象：侧栏固定助理；会话有真实状态、草稿和成果；检查区组织电脑与持续上下文；待处理聚合阻塞；资料库、技能、定时工作有生命周期。功能是否成立按流程验收。

## 不能照搬的假设

托管电脑承担常在线、模型适配与环境维护。本地Agent模式必须处理版本、认证、能力差异、睡眠、文件位置和无法强制审批的路径。API连通不等于工具可用，保存消息不等于执行，复制电脑外观不等于已有隔离和恢复。

以上官方资料不能证明成功率、模型策略或私有实现；后续竞品实测沿用[研究协议](research.md#5-后续实测协议)。
